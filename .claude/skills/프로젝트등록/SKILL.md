# 프로젝트등록 — ARISA 포트폴리오 등록

프로젝트 브리프(문서·회의록·계획서·자유 텍스트 무엇이든)를 받아 ARISA 통합 대시보드의 프로젝트 카드로 만든다.

**역할 분담이 이 스킬의 핵심이다.**
- **파싱·판단은 이 스킬(LLM)** — 브리프에서 무엇이 목표이고 무엇이 태스크·이슈인지 읽어낸다
- **검증·병합·저장·배포는 스크립트** — `00-system/02-scripts/portfolio-register.py`
- 스키마·중복·날짜·명부 검증을 손으로 하지 말 것. 반드시 스크립트를 통한다

---

## Step 0: 입력 확인

브리프가 이미 대화에 있으면 바로 Step 1로. 없으면 요청한다.

받을 수 있는 형태: 사업계획서·제안서 PDF, 회의록, 카톡/메일 원문, 자유 메모, 기존 분석 결과.

**등록 전 반드시 확인할 4가지** — 브리프에 없으면 사용자에게 묻는다.
1. **PM** (없으면 등록 불가)
2. **기간** (start / end / dday) — "올해", "3분기까지" 같은 표현은 실제 날짜로 환산해 제시하고 확인받는다
3. **참여 멤버** — 사내 직원만. 명부(`arisa-employees.json`) 이름으로 정규화
4. **외부 파트너** — 사외 협업자가 있으면 **이름과 이메일을 반드시 받는다**

브리프에 사외 인물이 등장하면(현지 파트너·프리랜서·협력사 담당자·셰프·디자이너 등)
**이름만 적고 넘어가지 말고 이메일을 물어본다.** 스크립트가 이름·이메일 중 하나라도
없으면 등록을 중단한다(경고가 아니라 `✖` 중단). 연락처 없는 파트너가 카드에 쌓이면
인수인계 시점에 그 사람이 누구인지 추적할 수 없기 때문이다.

이메일을 당장 확보할 수 없으면 **그 파트너만 빼고 등록한 뒤**, 확보되는 대로
`--partner` 로 추가한다. 임시 이메일이나 추정 주소를 지어내지 않는다.

## Step 1: 컨텍스트 로드

```bash
# 명부 — 담당자 이름 정규화·팀 확인
cat 00-system/02-scripts/arisa-employees.json

# 기존 프로젝트 — 같은 프로젝트가 이미 있는지(있으면 병합 모드)
ls 00-system/01-templates/_data/projects/
```

이름이 비슷한 기존 프로젝트가 있으면 **새로 만들지 말고 그 id로 병합**한다. 백필로 생성된 껍데기 카드(`origin: assign-backfill`, 기간이 1주일 이하, 태스크 2~3건)가 이미 있는 경우가 많다.

## Step 2: 브리프 → 구조화

`brief` 18개 필드에 매핑한다. **모르는 건 비워둔다. 지어내지 않는다.**

| 필드 | 담을 내용 |
|---|---|
| `name` | 정식 프로젝트명 (약칭 아님) |
| `code` | 과제번호·계약번호·프로젝트 코드 |
| `client` | 발주처·클라이언트 |
| `type` | 사업 유형 (국가R&D / 브랜드 팝업 / 컨설팅 …) |
| `location` | 현장·테스트베드 위치 |
| `pm` `status` | PM / 컨디션(기본 `In Progress`) |
| `start` `end` `dday` | 기간·마감 |
| `opPeriod` | 기간 부연 (단계 구분, 행사일 등) |
| **`summary`** | **프로젝트 정의** — 무슨 사업이고 우리가 어떤 위치인지. 카드 첫 화면 |
| `req` | 클라이언트 요구사항·계약 조건 |
| **`goal`** | **올해(당해 기간) 목표** — 무엇을 달성하면 성공인지 |
| `kpi` | 정량 지표. 숫자와 검증 방법을 함께 |
| `critical` | 실행 주요포인트 — 순서·전제조건·병목 |
| `deliverables` | 산출물 목록 |
| `risk` | 주의사항 (상세 문제는 issues로, 여기엔 요약·참조) |

`summary`와 `goal`은 사실상 필수다. 둘이 비면 카드가 껍데기가 된다.

### 태스크 추출

**해야 할 업무만 등록한다.** 완료된 일, 배경 설명, 의사결정 기록은 태스크가 아니다.

```json
{"division":"사업기획","task":"외부평가 기관 섭외","owner":"배성원",
 "start":"2026-09-15","end":"2026-10-31","status":"Not Started","progress":0}
```

- `division` — 담당자의 **팀 기준**(명부 team). 경영 / 사업기획 / 공간팀 / 기획팀 / 운영팀
- `owner` — 명부 이름으로 정규화. 미정이면 PM
- `status` — `Not Started` / `In Progress` / `Done` (셋뿐)
- **날짜는 필수**. 브리프에 없으면 앞뒤 맥락으로 추정한 뒤 **추정임을 사용자에게 알리고 확인받는다**
- 담당자 배분은 **팀 성격을 따른다** — 예산·정산·인증→사업기획 / 설계·시공·샘플→공간팀 / 전략·대외·보고→PM

### 이슈 추출

미해결·미확정·리스크·충돌을 담는다. 완료된 사항은 넣지 않는다.

```json
{"issue":"이월예산 41,414천원 집행계획 미수립 — 연말 미집행 시 회수","division":"예산","status":"Open"}
```

- `issue` — **한 줄에 문제와 영향까지**. "예산 미정" 같은 라벨은 쓸모없다
- `division` — 이슈 성격 (예산 / 일정 / 협업 / 평가 / 인허가 …)
- `status` — `Open` / `In Progress` / `Closed`

### 외부 파트너 추출

사내 명부에 없는 협업자는 `members` 가 아니라 최상위 `partners` 에 넣는다.
`members` 는 대시보드 **열람 권한**과 연결되므로 사내 직원 전용이다.

```json
"partners": [
  {"name":"진실","email":"jinsil@example.com","org":"유럽 AHQ(파리)","role":"현지 컨트롤"}
]
```

- `name` `email` — **필수**. 하나라도 없거나 이메일 형식이 아니면 스크립트가 등록을 중단한다
- `org` `role` — 선택. 소속과 이 프로젝트에서의 역할
- 이메일이 중복되면 같은 사람으로 보고 병합한다 (대소문자 무시)
- **partners 에 등록된 이름은 `tasks.owner` 로 쓸 수 있다** — 명부 미등록 경고가 나지 않는다.
  외부 파트너가 실제로 맡은 업무는 그 사람 이름으로 태스크를 만든다

기존 프로젝트에 파트너만 추가할 때는 브리프 JSON 없이 바로:

```bash
python3 00-system/02-scripts/portfolio-register.py --id <프로젝트id> \
    --partner "진실=jinsil@example.com=유럽 AHQ(파리)=현지 컨트롤"
```

## Step 3: 검증 (dry-run)

작성한 JSON을 스크래치패드에 저장하고 **반드시 dry-run 먼저** 돌린다.

```bash
python3 00-system/02-scripts/portfolio-register.py --input <경로>.json --dry-run
```

- `✖` 는 등록 중단 — 고치고 다시 돌린다
- `⚠` 는 경고 — 명부 미등록 인원, members 누락 담당자, summary/goal 없음. **사용자에게 알리고 판단을 받는다**
- 중복 skip 건수가 예상과 다르면 기존 카드와 겹친 것 — 확인 후 진행

## Step 4: 등록

```bash
python3 00-system/02-scripts/portfolio-register.py --input <경로>.json
```

자동으로 처리되는 것: 기존 파일 백업 → 병합 → 로컬 저장 → 맥미니(macmini-ts) 배포 → 원격 검증.

**병합 규칙**
- `brief` — 준 키만 덮어쓰기, 나머지 기존 값 보존
- `tasks` — `akey`(start\|task\|owner) 중복 skip, 추가만
- `issues` — 문구 중복 skip, 추가만
- `members` — 합집합
- `partners` — 이메일(소문자) 기준 병합, 같은 이메일이면 최신 값으로 갱신

옵션: `--no-deploy`(로컬만) / `--replace-tasks`(태스크 통째 교체, 기존 진행률 날아감 — 사용자 확인 필수)

> 통합 대시보드 서버는 요청마다 파일을 직접 읽으므로 **재시작 불필요, 즉시 반영**된다.

## 함께 하면 좋은 것

- **프로젝트 폴더**가 없으면 `10-projects/[다음번호]-[영문-케밥]/` 신설 + `[번호]-progress.md` 작성 제안
- 팀 공유가 필요하면 텔레그램 발송 (직원봇 `DAILY_REPORT_BOT_TOKEN`, chat_id는 `arisa-employees.json`의 `by_telegram_id`)

## 하지 말 것

- 프로젝트 JSON을 손으로 편집하기 (스키마·중복·백업이 깨진다)
- 맥미니에 전체 폴더 복사 (**배포는 해당 파일만**)
- 브리프에 없는 목표·KPI·날짜를 지어내기 — 비워두고 물어본다
- 완료된 일을 태스크로 등록하기
- 외부 파트너를 `members` 에 넣기 — 열람 권한이 사외로 새고, 명부 경고가 계속 뜬다
- **파트너 이메일을 추정해서 채우기** — 모르면 물어보고, 못 받으면 그 파트너는 빼고 등록한다
