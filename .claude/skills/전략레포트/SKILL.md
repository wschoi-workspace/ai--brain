# /전략레포트 — 맥킨지형 논증 구조 전략 보고서

**목적: 반박당하지 않는 문서를 만든다.**

이 스킬은 설득하지 않는다. 증명한다. 읽는 사람이 감동하는 대신 **결정**하게 만드는 것이 목표다.
설득 서사가 필요하면 `/혁신전략레포트`를 붙여 쓴다(§8 연계).

- **문법 원본**: 서울특별시 시정 주요분야 컨설팅 용역 보고서(맥킨지·삼일PwC, 2014) 334p

- **해부 가이드**: `00-system/01-templates/strategy-proposal-report-guide.html` — **작업 시작 전 반드시 Read**

## CORE 4원칙 (절대 준수)

1. **제목만 읽어도 논증이 완결된다** — 모든 장 제목은 종결된 문장. 명사구 제목 금지.
2. **어미로 확신도를 구분한다** — 사실(~함)·문제(~필요함)·권고(~제안함/~권고함)를 섞지 않는다.
3. **근거는 뒤로 민다** — 빼면 결론이 흔들리는 것만 본문. 나머지는 `[Back-up]`.
4. **제약을 먼저 말한다** — 못 하는 것을 제안자가 먼저 꺼내고 대안을 붙인다.

> "했다"가 아니라 "잘했다" — 합격선은 **고스트덱 통과**(§Step 3)다. 여기서 막히면 다음으로 가지 않는다.

## Step 0. 입력 확인

이미 대화에 분석·데이터가 있으면 Step 1로. 없으면 요청한다.
**분석을 새로 지어내지 않는다.** 입력에 없는 수치를 생성하지 말고, 부족하면 묻는다.

확인할 5가지 — 없으면 `AskUserQuestion`으로 1회에 묶어 묻는다.

| 항목 | 왜 필요한가 |
|---|---|
| **의사결정자와 결정 사항** | 이 문서로 누가 무엇을 결정하는가. 이게 없으면 구조가 안 선다 |
| **과업 질문 3~5개** | 답하기로 한 질문. 번호를 매겨 끝까지 유지한다 |
| **보유 데이터·분석** | 수치·인터뷰·리서치. 파일 경로 또는 텍스트 |
| **분량·형식** | 풀 리포트 / 핵심 덱 15~25장 / Exec Summary 1장 |
| **제약 조건** | 예산·법령·조직·일정 등 이미 아는 제약 (§Step 7의 재료) |

## Step 1. 과업 번호 확정 (블록 1)

답할 질문을 **3~5개로 번호 매겨 고정**한다. 이후 이 번호를 절대 바꾸지 않는다.

원문에서: ①미래 비전 ②본청–출연기관 재조정 ③조직 개편 ④인력 전문성 ⑤이슈사업 —
334페이지 내내 같은 번호를 쓰고, **각 챕터 도입부에 같은 레이아웃의 목차 카드를 반복**하며 해당 항목만 강조한다.
독자가 언제든 "지금 어디를 읽는지" 알게 하는 가장 싼 신뢰 장치다.

## Step 2. Governing Thought

보고서 전체를 떠받치는 **한 문장 결론**을 먼저 쓴다. 종결어미 포함. 이 문장이 흔들리면 전부 다시 짠다.

## Step 3. 고스트덱 — 액션 타이틀만 (게이트)

**모든 장의 제목만** 작성한다. 콘텐츠·디자인은 손대지 않는다.
`{프로젝트}/전략레포트-storyline.md`로 저장하고 사용자 확인을 받는다.

### 액션 타이틀 5규칙

**규칙 1 — 명사구가 아니라 종결된 문장**

| ❌ | ✅ (원문 실제 제목) |
|---|---|
| 서울시 경제지표 분석 결과 | "외부경쟁이 심해지는 가운데 서울시 경제 지표는 전국 대비 열위에 있으며…" |
| 조직 개편 현황 검토 | "시정 핵심과제 수가 47개로 타 도시 대비 과다하여 핵심 사업 부문에서의 성과 창출이 미흡한 상황임" |

**규칙 2 — 종결어미가 확신도를 표시한다**

| 어미 | 의미 | 용례 |
|---|---|---|
| `~함 / ~임` | 관측된 사실 | "제조업 종사자 비중이 급격히 하락하였음" |
| `~필요함` | 문제 제기 (아직 해법 아님) | "미래 경제성장의 동력 발굴이 필요함" |
| `~제안함` | 우리의 권고 | "기획조정실에 '핵심과제총괄관리과/팀'을 신설하여 운영할 것을 제안함" |
| `~요구됨 / ~예상됨` | 외부 조건이 만든 필연 | "재정건전성 강화를 위한 준비가 필요함" |
| `~권고함` | 제안보다 강한 확신 | "정부의 기금운용 정책 방향을 고려 시 1안을 권고하며…" |
| `~가능함` | 여지 — 결정은 발주처 몫 | "신규 채용 인력에 한해 개선안 적용하는 단기안 고려 가능함" |

> ⚠️ 전부 "~해야 합니다"로 통일하면 사실·해석·권고가 뭉쳐, 검토자가 **어디를 반박할지 몰라 전부를 의심**한다.
> 어미를 나누면 반박 지점이 좁아지고, 좁아진 반박은 방어할 수 있다.

**규칙 3 — 2줄 제목 = 조건 + 주장**
> [조건] "장기적으로 책임부시장제 도입을 통해 통솔범위 문제를 해결하며,
> [주장] 단기적으로는 1급 실장 조직의 직보 권한 부여와 회의운영체계 선진화를 제안함"

**규칙 4 — 말줄임표로 앞뒤 장을 잇는다**
연속 2장의 제목을 `…`로 연결해 한 문장을 두 장에 걸쳐 완성한다. (원문 p21→p22)

**규칙 5 — 대괄호 라벨로 위치를 표시한다**
`[경제][사회][환경]` 진단축 · `[1. 비전 관련 조직 미비]` 이슈번호 · `[Big data]` 해법대상 ·
`[Back-up]` 부록 · `[단기 개선안][장기 개선안][최종 제언]` 시간축·결론 ·
`예시적 / 참고용 / 추후 내부 결정 필요` 확정도

### 게이트 통과 기준
- 목차 없이 **제목만 순서대로 읽어 논증이 흐르는가**
- 과업 번호(Step 1)가 모든 장에 대응되는가
- 사실과 권고가 섞인 제목 **0건**

**통과 못 하면 여기서 재배열한다. 다음 Step으로 가지 않는다.**

## Step 4. 본문 / Back-up 판정

각 장에 묻는다 — **"이 장을 빼면 결론이 흔들리는가?"**

- 흔들린다 → **본문**
- 흔들리지 않고 질문받을 때만 필요 → **`[Back-up]`**

| 본문에 남기는 것 | `[Back-up]`으로 빼는 것 |
|---|---|
| 주장 1문장 + 뒷받침 도표 1개 | 해외·타사 사례 상세 |
| 이슈 요약(Summary) 장 | 지표 정의·산식·시뮬레이션 |
| 개선안·권고안 | 법령·조례·계약 원문 |
| 단기/장기 2트랙 | 인터뷰 지적사항 목록 |
| 실행 로드맵 | 운영 현황표 (1/2), (2/2) 연속 데이터 |

**목표 비율: 본문 65~75% / Back-up 25~35%**
(원문 실측 — 334p 중 `[Back-up]` 92p = 27.5%. 맥킨지 파트 21.9%, 삼일PwC 파트 34.0%)

> 본문 90% 초과 = 근거를 본문에 욱여넣음 · 본문 50% 미만 = 주장 없는 자료집

## Step 5. 근거 규율

- **모든 도표에 하단 출처 각주** — `자료: 통계청, 경제활동별 지역 내 총생산, 각 연도`
  (원문 실측 — 334p 중 출처 명시 190p = 56.9%)
- **정의·산식·제외항목은 위첨자 각주로** — 본문은 깨끗하게, 반박 지점은 찾을 수 있게
  > 각주 예: 고용유발계수 = 10억원당 고용인구(MICE 14.6명, 관광 12.8명 vs 산업 평균 9.8명)
- **확정도 라벨** — `예시적` / `참고용` / `추후 내부 결정 필요` / `[최종 제언]`
- **숫자 3중 체크 (CLAUDE.md 필수)** — 추출 → 신뢰출처 웹 대조 → 재대조.
  ⓐ수치 ⓑ단위(% vs %p) ⓒ귀속 ⓓ맥락 ⓔ출처 표기를 모두 확인.
  **불확실하면 지어내지 말고 자리표시자로 두고 확인 요청.**

## Step 6. 옵션 → 평가축 → 권고

핵심 제안은 하나만 던지지 않는다. 선택지를 펼치고 같은 잣대로 평가한다.
검토자는 "왜 이것인가"가 아니라 **"이 잣대가 맞는가"**를 검토하게 된다 — 훨씬 유리한 싸움이다.

| 단계 | 할 일 | 원문 사례 (집단에너지, p170–178) |
|---|---|---|
| ① 옵션 전개 | 축을 정해 **3~4개 안** 도출 | 소유·운영 주체 축 → 현행유지 / 별도조직 / SPC / 매각 |
| ② 평가축 선언 | **3개 고려사항을 본문에 명시** | 장기 전략 부합 · 가격 통제력 · 경제성 |
| ③ 평가 | 전 옵션을 전 축으로 채점 → 압축 | 4안 → 2안 |
| ④ 축별 심화 | 각 축을 `[Back-up]`으로 따로 증명 | NPV 30년 추정 등 |
| ⑤ 최종 제언 | 권고하되 남은 변수를 질문으로 남긴다 | 추가 판단 필요 사항 3개 나열 |

> **판단 보류의 정직함** — "두 옵션 모두 장단점이 존재하며 최종 판단에 시일이 소요될 것으로 예상되는 바,
> 추가적인 판단을 통한 정책 결정이 요구됨"(원문 p178).
> 결론을 못 낸 게 아니라 **결론의 조건을 밝힌 것**이다. 미확정이 오히려 전문성으로 읽힌다.

## Step 7. 현실적 제약 + 단기/장기 2트랙

### 7-1. 제약 블록 — 반박을 먼저 꺼낸다
모든 권고 옆에 **[제약] → [대응]**을 붙인다.

| 권고 | 제약 | 대응 |
|---|---|---|
| 부시장 증원 | 지방자치법 시행령 제73조 부시장 수 제한 | 특별법 제정 또는 지방자치법 개정 |
| 수익조직 신설 | 공공기관 법적 제약으로 본청 내 설치 불가 | 단기 내부 조직 → 장기 외부 법인 |
| 전 인력 전보 제한 | 과거 사례상 실현 가능성 극히 낮음 | 신규 채용 인력에만 적용 |

검토자가 발견할 반박을 제안자가 먼저 말하고 대안까지 붙이면, 반박은 리스크가 아니라 **이미 설계된 경로**가 된다.

### 7-2. 2트랙 — 항상 병기
| 한 벌만 낼 때 | 두 벌로 낼 때 |
|---|---|
| "이대로 못 합니다"로 전체 기각 | 단기안 채택 + 장기안은 로드맵에 존치 → **부분 채택 경로** 확보 |

원문은 조직도조차 "단기 조직도 예시"·"장기 조직도 예시" 두 장이다.

## Step 8. 실행 로드맵 + PMO

### 5열 표 (열 구성 고정)
| 과제 영역 | 실행 과제 | 성과 기준(KPI) | 실행 시점 | 실행 주체 |
|---|---|---|---|---|
| 세입 확대 | 세외수입 총괄관리 프로세스 강화 | 징수율 · 모니터링 주기(분기→월) | '14 하반기 | 재정사업단 |
| 재정 관리 | 재정준칙 도입 | 채무 총액한도 예산 대비 20% / 연 발행 3% 이내 | '14 운영 목표 | 예산담당관·재정담당관 |

### 분기 간트
개선과제별 `'N년 1Q~4Q` 단위 도입 일정. "언제까지"가 아니라 **"어느 분기에 무엇이 끝나 있는가"**.

### PMO 지정
> "개선과제의 실행을 전담 관리하는 **시장 직속 사후관리 기구(PMO) 운영**을 통해
> 프로젝트에서 도출된 개선과제의 실행을 리드하도록 함" (원문 p333)

보고서가 끝나는 지점에서 **누가 이 문서를 계속 들고 갈 것인가**를 지정한다.
제안 레포트라면 여기가 곧 "우리를 왜 계속 써야 하는가"의 자리다.

- [ ] 명사구 제목 0건 / 사실·권고 혼재 제목 0건
- [ ] 과업 번호가 첫 장부터 끝까지 동일한가
- [ ] 출처 각주 없는 도표 0건 / 단위(% vs %p) 정확한가
- [ ] Back-up 비율 25~35%
- [ ] 핵심 제안이 옵션 평가를 거쳤고, **평가축이 본문에 선언**되었는가
- [ ] 제약 없는 권고 0건 / 단기·장기 2트랙 병기
- [ ] 로드맵에 주체·시점·KPI 공란 0건 / PMO 지정
- [ ] 브라우저 렌더 확인 — JS 에러 0, 가로 스크롤 없음 (CLAUDE.md 배포 검증)

## 안티패턴

| 증상 | 왜 문제인가 | 교정 |
|---|---|---|
| "현황 분석" 제목 | 제목만 읽으면 아무것도 안 남는다 | 결론을 제목으로 (Step 3) |
| 전부 "~해야 합니다" | 전부가 의심 대상이 된다 | 어미로 확신도 분리 |
| 본문에 근거 전량 투입 | 결론이 근거에 묻힌다 | Back-up 분리 (Step 4) |
| 제안 1개만 제시 | 대안 질문 한 방에 무너진다 | 옵션 3~4개 × 평가축 3개 |
| 제약 언급 회피 | 심사장에서 상대가 대신 발견한다 | 제약 먼저 + 대안 병기 |
| 이상적 최종안만 | "우리 상황에선 못 함"으로 전체 기각 | 2트랙 병기 |
| To-do 나열 | 주체가 없으면 아무도 안 한다 | 5열 로드맵 + PMO |
| 입력에 없는 수치 생성 | 발각되면 문서 전체가 죽는다 | 자리표시자 + 확인 요청 |
