# /매트릭스 — 항목 → 축으로 가른 전략 매트릭스

> 구 이름 `/sankey` (2026-07-31 개명). 흐름도(Sankey)는 이제 렌더 3종 중 하나다.
> IR 파일명 `sankey-graph.json`과 검증기 `build_sankey.py`는 그대로다 — 바꾸면 기존 산출물이 전부 끊긴다.

## ⚠️ 시작 전에 먼저 물을 것 (2026-07-31 대표 요청)

**이 스킬이 소환되면 작업에 들어가기 전에 아래 3건을 꺼내서 어떻게 할지 묻는다.**
봉은사 매트릭스에서 미결로 남은 것들이다. 새 프로젝트라도 ①②는 렌더러 공통이라 그대로 걸린다.

| # | 미결 | 물을 것 |
|---|---|---|
| 1 | **E(비즈니스 모델) 열 기본 정렬** | 교차 최소(barycenter) ↔ 논리 순서(대중→고단가→도매→기반→배제) 중 무엇을 기본으로? 지금은 교차 최소이고 툴바 '원본순'으로 전환된다 |

셋 다 정리되면 **이 블록을 지운다.** 남겨두면 매번 같은 걸 묻게 된다.

## 이 스킬이 하는 일

데이터가 **어디에서 출발해 무엇을 거쳐 어떤 결론에 닿는가**를 한 장으로 만든다.
그리고 `generate` 모드에서는 **어디로 흐르지 않았는가**를 찾아 질문으로 되돌려준다. 아이디어는 대개 후자에서 나온다.

핵심 설계: 입력이 무엇이든 **`sankey-graph.json`(IR) 하나로 낮춘다.** 렌더러는 IR만 안다.
어댑터가 늘어나도 화면은 하나로 유지된다.

```
입력 4종 ──(어댑터·LLM)──▶ sankey-graph.json ──(build_sankey.py)──▶ 검증·빈틈탐지 ──▶ 인터랙티브 HTML
```

**역할 분담이 중요하다.** 매핑 판단(어느 필드가 어느 단계인가, 결론 문장이 무엇인가)은 LLM이,
산술·검증·탐지는 스크립트가 한다. 숫자를 LLM이 눈대중으로 세지 않는다.

## 파이프라인

### STEP 1 — 입력 판별
경로나 붙여넣은 내용을 보고 어댑터를 고른다. 애매하면 **묻는다**.

| 신호 | 어댑터 |
|---|---|
| `80-r-tech/85-analysis-results/*/`, `analysis.json`, `*-2layer-results.json` | `rxr` |
| `*/perspective/perspective-map.json` | `mpcf` |
| R4 세션 JSON, 회의록 MD, 전사 텍스트 | `meeting` |
| 그 외 텍스트·CSV·JSON | `free` |

`adapters.md`의 해당 절을 읽고 실제 필드명을 확인한다. 추측해서 매핑하지 않는다.

### STEP 2 — 단계 설계 (사용자 확정 필수)
3~5단계 계층안을 제시하고 **반드시 확인받는다.** 여기가 결과 품질을 좌우한다.
가능하면 **두 가지 안**을 낸다 (예: ①원인→대응→결과 ②주체→이슈→상태→결론).

지켜야 할 것:
- 마지막 단계는 **항상 `role: "conclusion"`**. 결론 없는 흐름도는 이 도구의 산출물이 아니다.
- **데이터가 지지하지 않는 단계를 만들지 않는다.** 흐름이 예뻐 보이려고 중간 열을 하나 더 넣는 순간 거짓이 된다.
  (실제로 불교 분석은 4단계가 아니라 3단계가 맞았다 — `examples/buddhism-graph.json` 참고)
- `axis`를 정한다: 주제 비교면 `topic`, 시점 전이면 `time`. 시간축은 `flow-grammar.md` §3 규칙을 그대로 따른다.

### STEP 3 — 렌더 모드 + value 기준 결정

**먼저 `meta.render`를 정한다. 데이터에 양이 있는가?**

| 데이터 · 목적 | render | 결과 |
|---|---|---|
| 건수·금액·비중이 실제로 있다 | `sankey` (기본) | 두께 있는 리본. 어디로 얼마나 갔는지 보인다 |
| 셀 것이 없다 — 컨셉 개발, 자산 매핑, 관점 재조합 | `map` | 가는 실선 + 요소 나열 + 그룹 블록 + 컨셉 카드 |
| **눌러서 찾아야 한다** — "이건 어디에 속하나", "이 조건에서 뭐가 되나" | `decision` | 양방향 의사결정 화면. Concept 탭 + 중앙 열 + 좌측 필터 + 우측 경로 |

`map`을 고르면 `references/flow-grammar.md` §4를 읽고 `kind`(item/group/card)·`members`·`caption`을 채운다.
**집계 노드로만 그리면 눌러도 안 좁혀진다** — 원자(개별 항목)가 있으면 `atoms` + `axis_map`을 함께 넣어라.
그러면 요소를 누를 때마다 링크와 건수가 다시 계산되는 의사결정 화면이 된다(§4 원자 레이어).
**`members`의 이름은 곧 선의 도착점이다** — 상대 노드의 `label`과 글자 그대로 같아야 그 줄로 선이 들어간다.
`links[]`에 없는 멤버는 화면에 흐린 이탤릭으로 드러난다.

그다음 `count` / `evidence` / `equal` 중 하나를 고르고 `value_note`에 무엇을 세는지 적는다.
(`map`이면 `equal` 고정)
- 수치가 없는 정성 데이터에 **임의 가중치를 만들지 않는다.** `equal`을 쓰고, 화면에 "두께는 양이 아님" 배지가 뜨게 둔다.
- 비율을 건수로 환산했으면(멀티라벨 토픽 등) 그 사실을 `value_note`에 반드시 남긴다.

### STEP 3.9 — 축이 여러 개면 IR을 손으로 쓰지 말고 제너레이터를 쓴다

원자(개별 항목)를 여러 축으로 가르는 매트릭스는 `scripts/matrix_gen.py`가 만든다.
config 하나에 **"무엇을 어느 축으로 나눌 것인가"만 선언**하면 원자별 축 값·노드·IR이 나온다.

```bash
cd .claude/skills/매트릭스/configs
cp _template-matrix.py <프로젝트>-matrix.py                  # ← 새로 만들 때는 템플릿부터
python3 ../scripts/matrix_gen.py <프로젝트>-matrix.py        # → IR 생성 + HTML까지
python3 ../scripts/matrix_gen.py <config>.py --json-only    # IR만
```

**`configs/_template-matrix.py`는 그대로 실행된다**(데모 원자 6건 내장). 먼저 돌려 화면을 보고
`load()`와 축 정의를 실제 데이터로 갈아끼우는 순서를 권한다. 아래 4패턴이 전부 들어 있다.

config가 선언하는 것 (실물: `configs/bongeunsa-matrix.py`):

| 이름 | 내용 |
|---|---|
| `load()` | 원자 원본 목록을 반환 |
| `ATOM` | 원본에서 `id`/`label`/`summary`/`blocked`/`evidence`를 뽑는 함수들 |
| `STAGES` | 열 정의 — `axis`(축 이름) + `nodes`(각 노드의 `match` 판정) |
| `CONCLUSIONS` · `SLOTS` · `WHITESPACE` | 선택 |

**`pick` 규칙이 급소다.** 다중 태깅을 전부 이으면 밀도 80%의 완전 이분 그래프가 되어 경로가 사라진다.
- `'all'` — 걸리는 대로 전부 (기본)
- `'first'` — 우선순위상 첫 번째만 (배타 축)
- `('rare', 2)` — 희소한 순으로 2개만. **흔한 값보다 희소한 값이 그 원자를 특징짓는다**

출력에 축별 **원자 커버리지**가 찍힌다(`원자 커버 109/116 ← 7건 미분류`). 미분류가 뜨면 판정 규칙에 구멍이 있는 것이다.

#### 매트릭스 4패턴 (전부 봉은사에서 실측으로 얻은 것)

**① 주력 1개 + 연계 n개 — 상위를 하나로 고정하지 않는다**
그룹당 상위 하나로 묶으면 실제로 있는 교차가 화면에서 통째로 사라진다.
연계는 **두 층**으로 선언한다. 그룹 층만 쓰면 큰 그룹이 통째로 틀린다:

| 층 | 언제 | 봉은사 실물 |
|---|---|---|
| `ALSO_GROUP` | 그룹 전체가 그 모델에 걸림 | G7 대관 → BM-5(컨벤션·MICE), G9 멤버십 → BM-4(커뮤니티) |
| `ALSO_ITEM` | 같은 그룹 안에서 아이템마다 다름 | G10 26건 → 전시 패키지 7건은 박물관형, 프로그램 확산 6건은 체험형, 기업 콜라보 1건은 F&B, 나머지 14건은 원래 모델 단독 |

**연계는 근거를 주석에 남긴다.** 다 이으면 밀도 80% 완전 이분 그래프로 되돌아간다(봉은사 10 → 22개, 밀도 20%).
⚠️ **미가동(0건) 판정은 연계를 넣기 전엔 못 믿는다** — BM-4의 '후원·헌금 0건'이 G9 연계 하나로 사라졌다.

**② 판정 재료는 라벨이 아니라 원문 문장이다**
문장이 이미 답을 말한다("연회비를 내면", "정부 지원을 받으며 유료 운영", "임대 수익을 걸러내는").
라벨 1차 판정 → `_EXCEPT`(문장을 읽고 주 값 교정) → `_ALSO`(한 원자가 말하는 두 번째 값)의 3층으로 쌓는다.
**키워드를 문장에 그대로 돌리지 않는다** — 오탐이 크다(영대공양의 '공양'이 다이닝으로 걸린다).
문장은 읽어서 **표로 고정**한다. 매핑 판단은 LLM, 집계는 스크립트.

**③ 상세 열의 0건 칸이 산출물의 절반이다**
`MODEL_ITEMS`처럼 "이 상위가 가질 수 있는 항목"을 선언해두면, 원자가 없는 칸이 흐리게 남는다 —
그게 **"가능한데 아직 안 하는 것"**이다. 리서치로 세우는 칸은 **없으면 그 모델이 성립하지 않는 것만** 남긴다.
남발하면 0건이 흔해져 경고로 안 읽힌다(봉은사 21개 → 2개로 줄여 되살렸다).

**④ 흐름이 아니라 조건인 열은 `filter_only: true`**
법 관문처럼 "무엇으로 흘러가는" 게 아니라 "무엇을 자르는" 열. 선을 지우고 앞뒤를 직접 잇는다.
누르면 필터로는 그대로 작동하고, 툴바 `<이름> 연결선` 토글로 선을 되살릴 수 있다.
**걸린 필터는 헤더 밑 칩(`#chips`)에 항상 뜬다** — 없으면 선이 없는 열은 눌러도 "반응이 없다"고 읽힌다.

### STEP 4 — IR 작성 → 검증
`sankey-graph.json`을 쓰고 검증기를 돌린다.

```bash
python3 .claude/skills/매트릭스/scripts/build_sankey.py <graph.json> -o <report.html>
```

옵션: `--check-only` 검증만 · `--absorb` 중간 유실을 '미분류' 노드로 흡수 · `--strict` WARN도 실패로

검증기가 자동으로 하는 일:
- R1~R5 검사(결론 단계 존재·DAG·참조 무결성·값 정합·근거 있는 결론)
- `orphan` / `dead_end` / `hub` 플래그 부여
- `generate` 모드면 빈틈 7종 탐지 + 조사 맞춘 질문 문장 생성
- 총량 보존 대조 (시작 유량 → 결론 유량)

**FAIL이 하나라도 나오면 HTML을 만들지 않고 멈춘다(exit 1).** 고쳐서 다시 돌린다.
WARN은 사람에게 그대로 보고한다 — 숨기지 않는다.

### STEP 5 — 렌더 검증 후 보고
"만들었다"와 "보인다"는 다르다. **브라우저로 열어 확인하기 전에는 완료가 아니다.**

```bash
# file: 프로토콜이 막힌 환경에서는 로컬 서버로
cd <출력 폴더> && python3 -m http.server 8899 --bind 127.0.0.1 &
```
Playwright로 확인할 것:
1. 콘솔 **JS 에러 0** (favicon 404는 무관)
2. `.node` / `.link` 개수가 IR의 `nodes` / `links` 길이와 **일치**
3. 노드 y 겹침 0, 라벨 잘림 0
4. 인쇄 미리보기 버튼을 눌러 근거 부록이 실제로 보이는지

**PNG·PDF를 만들지 않는다.** 검증은 `browser_evaluate` 반환값으로만 한다.

산출물은 입력 데이터가 있는 프로젝트 폴더의 `[프로젝트]/matrix/` 아래에 둔다
(봉은사는 개명 전에 만들어 `sankey/`에 있다 — 기존 폴더는 옮기지 않는다)
(`sankey-graph.json` + `sankey-report.html`). 자유 입력이면 사용자에게 위치를 묻는다.

## 화면에서 되는 것 (사용자에게 안내할 내용)

**공통** — 노드에 마우스를 올리면 그 노드가 닿는 상·하류 전체 경로만 남는다.
노드·연결을 클릭하면 우측 패널에 근거 원문과 출처가 뜬다(근거가 없으면 "근거 미기재"라고 명시).
인쇄 미리보기를 누르면 근거·결론·빈틈이 부록 표로 펼쳐지고, 그대로 인쇄하면 A4 가로.

| `sankey` 전용 | `map` 전용 |
|---|---|
| 단계 머리글 클릭 → 그 단계를 접고 상·하류 직결(유량 비례 보존) | **선이 그룹 안 같은 이름 줄로 정확히 들어감** |
| 범례 클릭 → 계열별 on/off | **노드 클릭 → 강조 고정(pin).** 마우스를 떼도 유지 |
| 정렬 토글 → 값순 / 이름순 / 원본순 | 정렬 토글 → 교차 최소 ↔ 원본순 (교차 40%↓) |
| | 선 색 = 출발 계열, 마지막 두 열은 세로로 짝 정렬 |
| | 기본 흰 배경(기획서용), 다크 토글 |

## 흔한 실수

| 증상 | 원인 | 처방 |
|---|---|---|
| `역방향 또는 동일 단계 연결` FAIL | 링크가 단계 순서를 거스름 | 단계 순서를 다시 보거나 노드의 `stage`를 고친다. d3-sankey는 순환에서 무한루프에 빠지므로 우회하지 않는다 |
| 빈틈이 수십 건 쏟아짐 | 결론 매핑이 배타적인데 그걸 빈틈으로 셈 | 검증기가 이미 결론 단계를 제외한다. 그래도 많으면 노드를 묶어 40개 이하로 줄인다 |
| 총량 보존 WARN | 중간에서 유량이 샘 | 매핑 누락일 가능성이 높다. 진짜 유실이면 `--absorb`로 '미분류' 노드에 흡수한다 |
| 노드가 너무 많아 안 읽힘 | 40개 초과 | 상위 N개 + `기타(n건)`로 접되, **접었다는 사실을 화면과 보고에 반드시 명시**한다 |
| 결론이 다 똑같이 굵어 보임 | Sankey는 근거 두께를 안 그림 | `thin_path` 탐지가 ⚠ 배지를 붙인다. 그 경고를 지우지 않는다 |

## Sankey의 한계 (사용자에게 미리 알릴 것)

**노드에서 흐름이 합쳐지면 출처 정보가 사라진다.** 예를 들어 '감성' 열에서 여러 토픽이 '긍정'으로 합쳐지면,
그다음 열에서는 어느 토픽에서 온 긍정인지 그림이 기억하지 못한다.
그래서 중간에 합류가 심한 축을 넣으면 오히려 정보가 준다. 이럴 땐 그 축을 단계가 아니라
**링크 분기 조건**으로 쓰는 게 낫다 (`examples/buddhism-graph.json`이 감성을 그렇게 처리했다).

## 제너레이터 (재생성용)

| config | 산출 | 무엇 |
|---|---|---|
| `configs/_template-matrix.py` | (자체 실행) | **새 매트릭스의 출발점.** 4패턴이 다 들어 있고 그대로 돌아간다 |
| `configs/bongeunsa-matrix.py` | `strategy-matrix.html` **+** `decision-map.html` | 9열 상세 매트릭스 · 원자 116 · D-1 77항목 · C→D 연계 22 |
| `configs/bongeunsa-matrix-overview.py` | `strategy-matrix-overview.html` | 6열 개요 — 법적 검토가 출발점. **축 판정은 위 config를 import해 재사용**하고 열 배치만 다르다 |
| ~~`configs/bongeunsa-decision.py`~~ | — | 폐기(2026-07-31). 통합 전후 대조용으로만 남김 |

**한 config가 두 화면을 만든다.** `STAGES[].dec`가 각 열을 Decision Map에서 어떻게 쓸지 정하고
(`tab`·`col`·`detail`·`filter`·`filter+col`·`skip`), config에 `DECISION='...html'`을 적으면 매트릭스와 함께 나온다.
IR은 하나다 — `build_sankey.py <ir> --render decision`이 화면만 바꿔 뽑는다(원본 IR은 안 건드린다).

**같은 데이터로 세 화면을 만들 때의 분업**: 개요(한 장 요약) / 상세(파고들기) / 탐색(눌러서 찾기).
열 배치만 다른 config를 나란히 두고, **축 판정은 한 곳에만 둔다** — 두 곳에 두면 실제로 한쪽이 낡는다
(Decision Map이 그렇게 되어 연계·수익항목이 통째로 빠져 있었다).

봉은사 config 상단 주석에 **확장 예정 지점**이 표시돼 있다 — Target 해석(리서치 자료 대기),
컨셉 해석 구조(옵션 열, order 8 자리), D-1 매출 산식(객단가·회전이 들어오면 항목마다 금액을 붙인다).
