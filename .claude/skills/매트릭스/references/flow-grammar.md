## 1. sankey-graph.json 스키마

```jsonc
{
  "meta": {
    "title":       "봉은사 구 웨딩홀 — 인식 흐름",   // 필수
    "subtitle":    "네이버 블로그 멘션 2,809건",      // 선택
    "source":      "90-archive/30-buddhism-brand-analysis/data/analysis.json", // 필수, 원본 경로
    "generated_at":"2026-07-30",                    // 필수
    "axis":        "topic",        // "topic" | "time"           필수
    "mode":        "structure",    // "structure" | "generate"    필수
    "value_basis": "count",        // "count" | "evidence" | "equal"  필수
    "value_note":  "포스트 건수"    // value_basis 설명, 화면 배지에 그대로 노출
  },

  "stages": [
    { "id":"s1", "label":"세그먼트", "order":0, "role":"origin",     "note":"" },
    { "id":"s2", "label":"인식 토픽", "order":1, "role":"structure",  "note":"" },
    { "id":"s3", "label":"감성",     "order":2, "role":"synthesis",  "note":"" },
    { "id":"s4", "label":"결론",     "order":3, "role":"conclusion", "note":"" }
  ],

  "nodes": [
    {
      "id":      "n-buddhism",          // 필수, 고유
      "stage":   "s1",                  // 필수, stages[].id 참조
      "label":   "불교",                 // 필수
      "value":   1084,                   // 선택. 없으면 링크 합계로 산출
      "category":"seg-buddhism",        // 선택. 색상·필터·계보 묶음의 기준
      "summary": "멘션 1,084건",         // 선택, 근거 패널 상단
      "evidence":[ { "quote":"...", "src":"analysis.json#불교.n" } ],  // 선택
      "flags":   []                      // "orphan" | "hub" | "dead_end" (검증기가 자동 부여)
    }
  ],

  "links": [
    {
      "id":        "l-001",             // 선택. 없으면 "src>tgt"로 자동 생성
      "source":    "n-buddhism",        // 필수, nodes[].id
      "target":    "n-topic-practice",  // 필수, nodes[].id
      "value":     462,                 // 필수, > 0
      "confidence":"high",              // 선택: high | medium | low
      "evidence":  [ { "quote":"...", "src":"..." } ],
      "note":      ""
    }
  ],

  "conclusions": [
    {
      "node_id":  "n-concl-lifestyle",       // 필수, role:"conclusion" 스테이지의 노드
      "statement":"불교는 이미 라이프스타일 시장 1위다",  // 필수
      "so_what":  "종교 카테고리가 아니라 웰니스 카테고리로 포지셔닝해야 한다",
      "support":  ["l-003","l-011"],          // 필수, 최소 1개. links[].id 참조
      "counter":  ["l-027"]                    // 선택, 반대 근거
    }
  ],

  "whitespace": [                              // mode:"generate"에서만 채움
    {
      "type":    "empty_cell",
      "where":   ["n-seg-christian","n-topic-practice"],
      "question":"기독교 세그먼트에 수행·명상 언급이 왜 0인가?",
      "idea":    "'수행'을 종교 밖 언어로 번역한 프로그램 — 경쟁자 없는 구간"
    }
  ]
}
```

## 2. 필수 규칙

### R1. 마지막 스테이지는 반드시 `role: "conclusion"`
`stages`를 `order` 오름차순 정렬했을 때 마지막 원소의 `role`이 `"conclusion"`이 아니면 **검증 실패**.
"결론 카테고리화"를 스키마 수준에서 강제한다. 결론 없는 흐름도는 이 도구의 산출물이 아니다.

`role` 4종의 의미:
| role | 뜻 | 개수 |
|---|---|---|
| `origin` | 원천 — 데이터가 들어오는 지점 | 정확히 1개 (order 0) |
| `structure` | 구조화 — 분류·관점·토픽 | 0개 이상 |
| `synthesis` | 수렴 — 패턴·군집·상태 | 0개 이상 |
| `conclusion` | 결론 카테고리 | 정확히 1개 (마지막) |

권장 단계 수는 3~5. 6단계를 넘으면 화면에서 읽히지 않으므로 경고한다.

### R2. value_basis — 링크 두께의 근거를 반드시 밝힌다

| value_basis | 뜻 | 쓸 때 |
|---|---|---|
| `count` | 실제 건수 | 멘션 수·응답 수·발생 횟수 등 셀 수 있는 것 |
| `evidence` | 근거 인용 개수 | 정성 자료지만 인용 수로 비중을 말할 수 있을 때 |
| `equal` | 전부 1 고정 | 정성 자료. **두께에 의미가 없다** |

`equal`인 경우 렌더러 헤더에 **"두께는 양이 아님 — 연결 유무만 표시"** 배지가 뜬다.
정성 데이터에 임의 가중치를 넣어 굵게 그리는 순간 자료가 거짓이 된다. 추정치를 실측치처럼 그리지 않는다.
(CLAUDE.md 숫자·통계 검증 3중 체크의 연장선)

### R3. DAG 강제 — d3-sankey는 순환에서 무한루프에 빠진다

검증기가 막는 것:
1. **역방향 링크 금지** — `stage(source).order >= stage(target).order`인 링크는 **거부**. 같은 스테이지 내부 링크도 거부.
2. **스테이지 건너뛰기** — `order` 차이가 2 이상이면 허용하되 `warnings`에 기록하고 화면에 점선으로 표시.
3. **고립 노드는 삭제하지 않는다** — in/out 링크가 0인 노드는 `flags:["orphan"]`을 붙여 살려둔다. 빈틈 그 자체가 정보다. 렌더러는 `fixedValue`로 최소 높이를 주고 점선 테두리로 그린다.

### R4. 값 정합
- 링크 `value`는 항상 > 0. 0이나 음수는 거부.
- 노드 `value`를 명시했다면 `Σ(들어오는 링크) ≤ value` 이고 `Σ(나가는 링크) ≤ value`. 위반 시 경고(거부는 아님 — 중도 이탈이 실제로 있을 수 있다).
- 중간 스테이지에서 유실이 발생하면(들어온 양 > 나간 양) 결론 스테이지에 **`미분류`/`추적 실패` 노드를 만들어 흡수**한다. 흐름 보존이 깨진 Sankey는 읽는 사람을 속인다.

### R5. 참조 무결성
- `nodes[].stage` → `stages[].id` 존재
- `links[].source/target` → `nodes[].id` 존재
- `conclusions[].node_id` → `role:"conclusion"` 스테이지의 노드
- `conclusions[].support[]` → `links[].id` 존재. **`support`가 빈 결론은 거부** — 근거 없는 결론을 자동 생성하지 않는다.

## 3. 시간축(`axis: "time"`) 규칙

시간축은 Sankey에서 가장 쉽게 망가진다. 같은 이슈가 시점마다 반복되면 순환처럼 보이기 때문이다.

- **스테이지 = 시점** (T1, T2, T3 …). 마지막은 여전히 `role:"conclusion"`.
- **노드 = "그 시점에서의 이슈 상태"**. 같은 이슈라도 시점마다 **별개 노드**를 만든다.
  동일 이슈 계보는 `category`로 묶는다 (예: `category:"issue-europe-ahq"`).
- **링크 = 상태 전이. 4종만 허용**:
  | 전이 | 뜻 | 링크 형태 |
  |---|---|---|
  | 유지 | 그대로 다음 시점으로 | 1 → 1 |
  | 분기 | 하나가 여러 갈래로 | 1 → N |
  | 병합 | 여럿이 하나로 | N → 1 |
  | 종결 | 더 이상 진행 안 함 | 1 → 종결 노드 |
- **종결된 이슈를 지우지 않는다.** 마지막 스테이지의 `종결(해소)` / `종결(방치)` / `종결(폐기)` 노드로 흡수시킨다. 지우면 흐름 보존이 깨진다.
- **색상은 `category` 기준** — 한 이슈가 시간을 타고 어떻게 변형·소멸했는지 한 줄로 읽힌다.

## 4. 렌더 모드 — `meta.render`

같은 IR을 세 가지로 그린다.

| | `sankey` (기본) | `map` | `decision` |
|---|---|---|---|
| 무엇 | 두께 있는 리본 | 가는 실선 + 요소 나열 | **양방향 의사결정 화면** |
| 쓸 때 | 건수·금액이 있을 때 | 관계만 있을 때 | "이건 어디에 속하나 / 이 조건에서 뭐가 되나"를 **눌러서** 찾을 때 |
| 방향 | 좌→우 흐름 | 좌→우 흐름 | 없음 — 어느 열을 눌러도 나머지가 좁혀진다 |
| 검사 | R4·총량 보존 | 미적용 | 미적용 (R1·DAG도 면제) |
| 템플릿 | `sankey-report.html` | `concept-map.html` | `decision-map.html` |

### decision 모드

흐름도가 아니라 **필터 화면**이다. `links`를 쓰지 않고 관계를 **노드 필드**로 표현한다.

```jsonc
"stages": [                       // role이 배치를 정한다
  {"id":"concept","role":"entry"},      // 상단 탭 — 시작점
  {"id":"bm","role":"structure"},       // 중앙 열
  {"id":"cat","role":"structure"},
  {"id":"svc","role":"structure"},
  {"id":"legal","role":"gate"},         // 중앙 마지막 열 — 필터 겸 관문
  {"id":"target","role":"filter"},      // 좌측 필터 패널
  {"id":"research","role":"data"}       // 우측 데이터 레이어
],
"nodes": [
  {"id":"E-0612","stage":"svc","label":"봉안당 분양",
   "parent":"G9",            // Service Category (Level 1 → Level 2)
   "bm":"ax3",               // 어느 수익모델로 도는가
   "legal":"Tier2",          // 법 판정
   "blocked":false,          // true면 취소선 — 현행 불가
   "concepts":["C-B","C-A"], // 어느 컨셉에서 살아남는가
   "targets":["t-bud","t-biz"]},
  {"id":"bm3","stage":"bm","label":"BM-3 복합임대형","verdict":"조건부"},
  {"id":"rs-S4-O4","stage":"research","label":"Location","items":["유동인구","체류시간"]},
  {"id":"slot0","stage":"research","slot":true,"label":"◻︎ 기업 수요 데이터","summary":"필요 — …"}
]
```

**작동 원리**: '살아 있는 서비스 집합'이 진실이고 나머지 열은 전부 거기서 파생된다.
그래서 정방향(BM→서비스)과 역방향(서비스→BM)이 같은 계산 하나로 성립한다.
`verdict`는 판정 배지, `blocked: true`는 취소선, 조건에서 빠진 것은 회색이 된다.

### map 전용 필드

```jsonc
"meta": { "render": "map", "accent": "#00B894" }   // accent는 선택, 기본은 청보라
"nodes": [
  { "id":"a1", "stage":"s1", "kind":"item",  "label":"판전 · 추사 현판" },

  { "id":"ps-archive", "stage":"s2", "kind":"group",
    "label":"ARCHIVE",
    "summary":"무엇이 남고, 어떻게 남기며, 남은 것은 무엇이 되는가?\n유산 · 기록",  // \n은 줄바꿈
    "members":["판전 · 추사 현판","지정문화재 18건"] },                          // 강조색으로 나열됨

  { "id":"sc-B", "stage":"s4", "kind":"card",
    "label":"Scenario B", "caption":"긍정적 범위 — 전통 문화 복합공간",
    "summary":"A의 전부 + F&B와 큐레이션 리테일",
    "members":["연 46~65억 · baseline의 110~155%"] }
]
```

`kind` 3종:
- **`item`** — 텍스트 한 줄. 첫 열은 오른쪽 정렬, 중간 열은 가운데.
- **`group`** — 제목 + 설명 + 멤버 목록. 중간 열의 성격 묶음.
- **`card`** — 위아래 강조선 + 제목 + 부제 + 설명. **결론 단계에만 둔다.**

### map 규칙

1. `value_basis`는 **`equal`**로 둔다. 굵기를 안 쓰므로 다른 값을 넣으면 검증기가 경고한다.
2. 링크 `value`는 전부 1. 유량이 아니므로 합류·분기에서 정합을 맞출 필요가 없다.
3. **`members`의 이름은 곧 선의 도착점이다.** 멤버를 세로 목록으로 그리고, `links[]`에 같은 연결이 있으면 선이 **그 이름 줄로 정확히 들어간다.** 그래서 `members`에 적는 이름은 상대 노드의 `label`과 **글자 그대로 같아야** 한다.
   - `links[]`에 없는 멤버는 흐린 이탤릭으로 표시된다 — "목록에는 있는데 연결이 없다"를 숨기지 않는다.
4. 마지막 두 열의 노드 `category`를 맞추면(예: 구성요소와 카드 모두 `sc-A`) 두 열이 세로로 짝을 이뤄 배치된다. 이미지의 "Segment C ↔ Concept" 구조가 이것이다.
5. 노드가 60개를 넘으면 세로로 길어져 한 화면에 안 들어온다. 열당 25개 이하를 권한다.
6. **원자를 넣으면 필터가 켜진다** — 아래 참조.
7. 선 교차는 렌더러가 자동으로 줄인다(barycenter). 결론 열 순서와 `category` 묶음은 고정하고, 그 안에서만 재배치한다. 화면의 **정렬** 버튼으로 원본순과 오갈 수 있다.

### 원자 레이어 — `atoms` + `axis_map` (선택)

집계 노드만 있는 지도는 눌러도 좁혀지지 않는다. 링크가 **집계 결과로 박혀 있어** 다시 셀 수가 없기 때문이다.
원자를 넣으면 렌더러가 **필터를 걸 때마다 링크와 건수를 다시 센다.**

```jsonc
"axis_map": {            // 어느 stage가 원자의 어느 축인가. 이게 있어야 필터가 켜진다
  "s1":"target", "s2":"dir", "s3":"cat", "s4":"bm", "s5":"legal", "s6":"concept"
},
"atoms": [
  { "id":"E-0600", "label":"전통다원 · 오픈형",
    "axes": { "target":["t-intl","t-local"],    // 배열이면 여러 노드에 걸린다
              "dir":["d-cul"], "cat":"G1", "bm":"ax1",
              "legal":"t1", "concept":["C-A","C-B"] },   // ← 값은 반드시 '노드 id'
    "blocked": false, "summary":"…", "evidence":[…] }
],
"links": [],             // 비워둔다 — 있으면 진실이 둘이 된다
"meta": { "link_rule": {"strong":0.60, "weak":0.35} }   // 실선/점선/제외 임계
```

규칙:
1. **`axes`의 값은 노드 id여야 한다.** 원본 코드값(`"Tier1"`)이 아니라 그 축 노드의 id(`"t1"`). 검증기가 미해결 참조를 FAIL로 잡는다.
2. **`links`는 비운다.** 원자가 있으면 렌더러가 매번 집계하므로, IR에 링크를 함께 두면 두 진실이 어긋난다.
3. **라벨에 건수를 박지 않는다.** `"불교 신자 · 52"`처럼 써두면 필터를 건 순간 거짓이 된다. 라벨은 이름만(`"불교 신자"`) 두고 건수는 렌더러가 배지로 붙인다.
4. `conclusions[].support`는 이때 **원자 id**를 가리킨다(링크 id가 동적이므로).
5. 원자가 하나도 안 걸린 노드는 WARN으로 알린다 — 대개 "쓸 수 없는 칸"이거나 빈 슬롯이다.

**상세 열 — `stages[].atomic: true`**

원자와 1:1인 열(예: 서비스 116건)은 `atomic: true`를 준다. 그러면:

- **항상 전부 나열한다.** 목록 자체가 정보이고, 조건에 안 맞는 것은 흐려질 뿐 자리를 지킨다
- **위에서 들어오고, 다음 줄기 단계로 다시 합류한다.** 줄기(A→B→C→D→E)는 상세를 건너뛰고도 흐르므로
  두 해상도가 겹쳐 보인다 — 굵은 줄기(집계)와 가는 잔가지(개별).
  들어오는 쪽은 짝 정렬 덕에 **평균 9px·거의 수평**이고, 나가는 쪽은 M:N 수렴이라 낙차가 생긴다(116→10).
- **묶음이 정렬을 막지 않게 한다.** 뒤 열의 `category`를 판정·속성별로 잘게 나누면 묶음마다 한 개씩이라
  barycenter가 작동할 여지가 없어 앞 열과 순서가 어긋난다(실측 교차 1,282 → 묶음 단일화 후 631).
  구분이 필요하면 색이 아니라 **라벨 앞 기호**로 표시한다.
- 잎에는 강도 필터를 걸지 않는다 — 목록이므로 전부 남긴다. 대신 CSS에서 더 가늘고 옅게 그린다(`.detail`)
- 건수 배지를 생략한다(늘 1이라 무의미)
- **한 줄로 고정한다**(`nowrap` + 말줄임). 두 줄로 접히면 노드 하나가 35px이 되어 116개가 4,000px을 먹는다
- **앞 열과 세로로 짝을 맞춘다** — 앞 열의 순서를 그대로 쓰고, 각 묶음을 상위 노드와 같은 높이로 늘린다.
  이걸 안 하면 'G4'는 위에 있는데 그 서비스 10개는 한참 아래에 놓여 선이 대각선으로 길게 늘어진다(실측 983px → 87px)
- **해당 항목이 없는 자리도 빈 묶음으로 남긴다.** 개수가 어긋나면 두 열의 분배가 달라져 짝이 깨진다(실측 717px → 4px)

**상세 열이 계층이 되려면 항목마다 상위가 하나여야 한다.** 상위와 M:N인 축(예: '수익 방식'은 여러 수익모델에 걸친다)은
그대로 쓰면 묶음이 하나뿐이라 짝이 안 잡힌다 — **(상위 × 축) 조합으로 쪼개서** 각 항목의 상위를 하나로 만든다.
조합에 여러 건이 묶이면 건수 배지가 뜨고, 1건이면 생략된다.

**걸린 필터는 화면 상단에 늘 띄운다.** 조건을 걸어도 그게 어디에도 안 보이면 "눌러도 반응이 없다"가 된다 —
특히 선이 없는 열(`filter_only`)은 눌러도 그림이 안 움직여 아무 일도 안 일어난 것처럼 보인다.
헤더 밑 `#chips`에 `<열이름> · <값> ✕` 칩과 `남은 것 n/N건`을 render마다 다시 그리고, 칩을 누르면 그 조건만 푼다.

**한 항목이 여러 상위에 걸리는 축은 배열로 둔다.** 그룹당 상위 하나로 고정하면 실제로 있는 교차가
화면에서 통째로 사라진다(봉은사: 대관=MICE=전시, 멤버십=커뮤니티, 장묘=추모 커뮤니티가 전부 안 보였다).
주력 1개 + 연계 n개로 두되 **연계는 근거를 주석에 남긴다** — 다 이으면 밀도 80% 완전 이분 그래프로 되돌아간다(10개 → 18개, 밀도 16%).

**필터 전용 열 — `stages[].filter_only: true`**

어떤 열은 **흐름의 한 칸이 아니라 조건**이다(예: 법 관문 — 무엇으로 흘러가는 게 아니라 무엇을 자르는지를 말한다).
그런 열에 선을 그리면 상세 열에서 여기로 내려꽂히는 선이 화면을 덮는다(봉은사 실측 51개 선, 평균 낙차 1,251px·최대 3,065px).
`filter_only: true`를 주면:

- **선을 그리지 않고 앞뒤 열을 직접 잇는다** — 줄기에서 빠지므로 D 다음이 곧 Concept이 된다
- **누르면 여전히 필터로 작동한다** — 잃는 것은 선뿐이고 조건으로서의 기능은 그대로다
- 열 머리에 `필터` 태그, 노드는 점선 테두리 — 흐름이 아니라는 걸 형태로 말한다
- 고립(orphan) 판정에서 제외한다. 선이 없는 게 정상인 열이라 그대로 두면 전부 오탐이 된다
- 툴바에 `<열이름> 연결선` 토글이 생긴다. 켜면 다시 줄기에 껴서 선이 돌아온다(기본 꺼짐)

열이 7개를 넘으면 렌더러가 열 간격을 78px→46px로 줄이고, `atomic` 열에는 폭을 더 준다(이름이 길다).

화면에서:
- 요소를 누르면 **그 축의 필터**가 된다. 열마다 하나씩, 여러 열을 겹치면 AND
- 노드 순서는 **전체 기준으로 한 번 계산해 고정**한다. 필터마다 재정렬하면 노드가 튀어 보던 자리를 잃는다
- 0건이 된 노드는 흐려지고, 선은 실제로 사라진다

## 5. 검증기 출력 형식

IR을 만든 뒤 반드시 아래 항목을 점검하고 결과를 사용자에게 보고한다.

```
[검증] sankey-graph.json
  스테이지     4개 (origin 1 / structure 1 / synthesis 1 / conclusion 1)   OK
  노드         27개 (orphan 2, hub 1)                                      OK
  링크         41개                                                         OK
  DAG          역방향 0건                                                   OK
  건너뛰기     1건 (n-a → n-c, order 0→2)                                  WARN
  참조 무결성  미해결 참조 0건                                              OK
  결론         3개, support 링크 전부 유효                                   OK
  값 정합      유실 12건 → '미분류' 노드로 흡수                              WARN
  value_basis  count (포스트 건수)
```

**하나라도 FAIL이면 HTML을 만들지 않고 멈춘 뒤 사람에게 보고한다.** WARN은 화면에 표시한 채로 진행한다.
