# 리라이팅 가이드 — 마케터 관점으로 다시 쓰기 (2026-07-29)

> 대표 지시: "raw data는 두고, 설명이 너무 어렵다. 마케터 관점으로 문구를 정리해서 핵심 중심으로 쉽게."
> **독자 기준: 내부 팀·실무자.** 마케팅·기획 기본 용어(BM·타겟·객단가·리텐션)는 그대로 쓴다. 걷어낼 것은 **분석 방법론·통계 용어**다.

---

## 0. 무엇을 건드리고 무엇을 두는가

| 건드린다 | 그대로 둔다 |
|---|---|
| h3 제목 · lead · 본문 문장 | **표 · 수치 · 근거칩(`<span class="ev">`)** |
| 은유·수사 | HTML 구조 · CSS 클래스 |
| 방법론 서술 | 아젠다 개수와 순서 |
| 용어 | 결론 자체 |

**결론을 바꾸지 마라.** 같은 결론을 쉽게 말하는 작업이다. 판단이 바뀌면 그건 리라이팅이 아니라 재집필이다.

---

## 1. 다섯 가지 원칙

### ① 첫 문장이 답이다
배경 설명으로 시작하지 않는다. 결론을 먼저 쓰고 근거를 뒤에 붙인다.

| ✗ | ✅ |
|---|---|
| "수익성 논의는 진공에서 시작하지 않는다. 이 건물은 이미 돈을 벌어본 적이 있고…" | "넘어야 할 기준은 연 42억입니다. 예전 웨딩홀이 벌던 돈입니다." |

### ② 은유는 한 페이지에 하나까지
지금 본문은 "여덟 개의 관문", "차례로 좁아지는 문", "파이프", "채점표"가 한 문단에 겹쳐 있다. 은유가 겹치면 실체가 사라진다. **가장 좋은 은유 하나만 남기고 나머지는 사실 서술로 바꾼다.**

### ③ 방법론은 본문에서 뺀다
독자는 우리가 어떻게 분석했는지 궁금하지 않다. **결과만 필요하다.**

| ✗ 본문에서 제거 | ✅ 대체 |
|---|---|
| "elements.json에서 셀 수 있는 정의로 바꿨다" | (통째로 삭제) |
| "ARI 0.014로 판별력이 없어 기각" | "실제로 나눠보니 이 기준으로는 구분이 안 됐습니다" |
| "116개 요소를 직접 집계한 값이다" | (삭제 — 근거칩이 이미 그 역할을 한다) |
| "K-means 5시드 + 계층군집 3연결법" | "여러 방식으로 다시 묶어봐도 결과가 같았습니다" |
| "viability 태그를 집계하면" | "조건별로 살아남는 것을 세어보면" |

수치 자체는 남긴다. **"어떻게 셌는지"만 뺀다.**

### ④ 한 문장에 한 생각. 60자를 넘기지 않는다
문장이 길면 절을 잘라 두 문장으로 만든다. 접속사로 이어붙이지 않는다.

### ⑤ 매 아젠다 끝에 "그래서 무엇을 하나"
각 페이지 마지막에 실무 행동 한 줄을 남긴다. 없으면 그 페이지는 정보일 뿐이다.
형식: `<p class="lead">` 대신 `.callout` 한 줄, 또는 마지막 `<p>`에 **굵게**.

## 2. 용어 치환 사전 (필수)

내부 코드는 **첫 등장 시 사람 말로 쓰고 괄호로 코드 병기**, 이후에는 사람 말만 쓴다.

| 내부 코드 | 본문 표기 |
|---|---|
| C1 | **프리미엄이냐 대중이냐** |
| C2 | **종교시설이냐 문화시설이냐** |
| C3 | **법을 어디까지 볼 것이냐** (합법 범위 안 / 해석이 필요한 회색지대 / 제도를 바꾸는 것) |
| C4 | **본원 공사와의 관계** |
| C5 | (기각됨 — "지역이냐 글로벌이냐는 갈림길이 아니라 실행 방법이었습니다"로 서술) |
| C6 | **브랜드를 키울 것이냐 사업을 만들 것이냐** |
| Tier 1 | **지금 그대로 되는 것** |
| Tier 2 | **해석을 받아야 되는 것** (회색지대) |
| Tier 3 | **안 되는 것** |
| viability | **어떤 조건에서 살아남는가** |
| 5축 평가 / eval | **다섯 가지 기준으로 매긴 점수** (수익·브랜드·난이도·법·지속성) |
| S8-A / Option A | **A안** (Buddhist Cultural Destination은 첫 등장 시 1회만) |
| 슬롯 / 요소 / elements | (본문에서 쓰지 않는다) |
| 근거칩 E-0058 | (설명하지 않는다. 그냥 둔다) |
| 유권해석 | 그대로 쓰되 첫 등장 시 "**문체부에 공식 해석을 받는 것**" 한 줄 부연 |
| Governing Thought | **한 줄 결론** |
| 화이트스페이스 | **아직 아무도 안 하는 자리** |
| 크리티컬 패스 | **가장 먼저 풀어야 할 순서** |
| 객단가 · 리텐션 · BM · 타겟 · 페르소나 | **그대로 쓴다** (내부 팀 기준) |

## 3. 숫자 쓰는 법

- **숫자 앞에 맥락 한 마디**를 붙인다. "연 42억"이 아니라 "예전 웨딩홀이 벌던 연 42억"
- **비교 대상을 준다.** "116개 중 5개"처럼 분모를 함께 쓴다
- 근거 등급 규칙은 그대로 유지 — C등급(회색 점선 칩)은 여전히 **본문 수치 인용 금지**
- 수치를 나열하지 말고 **하나만 굵게**. 나머지는 표로 내린다

---

## 4. 문체

- 종결은 **"~합니다"** 로 통일한다. 지금은 "~다"체인데, 내부 공유·구두 설명에 그대로 쓰기 위해 경어체로 바꾼다
- 단정한다. "~로 보인다", "~할 수 있다"는 근거가 실제로 약할 때만
- **모르는 것은 모른다고 쓴다.** 이 원칙은 그대로다. 다만 표현을 쉽게: "자료 공백이 존재한다" → "이건 아직 조사가 안 됐습니다"
- 수사를 쌓지 않는다. 사실 → 그래서 무엇 순서

---

## 5. h3(제목) 다시 쓰기

지금 제목은 액션 타이틀이라 방향은 맞지만 **은유와 대시(—) 뒤 부연이 너무 길다.**

| 현재 | 고친 뒤 |
|---|---|
| 여덟 개의 관문을 동시에 통과한 것만 남는다 — 앞 단계는 뒤 단계의 상한을 깎기만 한다 | **할 수 있는 건 116가지인데, 다 거르면 0개가 남습니다** |
| 채점의 일곱은 계산이고 셋은 판단이다 — 무엇이 어느 쪽인지 먼저 밝힌다 | **점수를 매기기 전에, 무엇을 셀 수 있고 무엇은 판단인지 정합니다** |
| 이 건물의 성공은 세 번 채점된다 — 그리고 세 채점표는 같은 답을 정답으로 치지 않는다 | **같은 건물인데 성공의 기준이 세 개입니다. 서로 어긋납니다** |

규칙: **30자 내외. 대시 부연은 꼭 필요할 때만.** 핵심어 1~2개를 `<em>`으로 감싼다.

---

## 6. 하지 말 것

- 결론·판단·수치를 바꾸는 것
- 표를 지우는 것 (표는 오히려 늘려도 된다 — 문장보다 표가 쉽다)
- 근거칩을 떼는 것
- 새 CSS 클래스를 만드는 것
- 아젠다를 합치거나 나누는 것 (번호 체계가 깨진다)
- 없는 수치를 만드는 것
