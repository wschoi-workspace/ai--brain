# 봉은사 재구조화 — 슬롯 체계 v3 (2026-08-19, 단일 Destination 확정 반영)

> v2(10-STEP)에서 **단일 Destination 확정 구조**로 개정. STEP 1~7은 손대지 않고 **STEP 8~10만 재설계**한다.
> 기존 798개 요소는 전량 재사용하며, 폐기 슬롯의 요소는 **본문 키워드 기반으로 존에 재배치**했다(196건).
> 정본은 `merge_validate.py`의 `VALID_SLOTS`이며, 이 문서는 그 해설이다 — 둘이 어긋나면 코드가 맞다.

## 보고서의 핵심 질문
> **"봉은문화센터는 미래의 불교와 사회를 연결하는 어떤 플랫폼이 되어야 하는가?"**

## 확정된 구조 원칙 (v3 · 2026-08-19 대표 확정)
1. **A/B/C 비교 구조 폐기.** 세 안은 STEP 7까지의 사고 실험이었고 STEP 9 채점으로 종결됐다.
   STEP 8부터는 **하나의 Destination을 확정하고 그 타당성을 증명**한다.
2. **세 안은 경쟁안이 아니라 Zone/Revenue Engine으로 재배치**한다.
   구 A(도달) → 전시·리테일 존, 구 B(깊이) → 체험 존, 구 C(파급) → 리테일·IP 존.
3. **STEP 9의 평가 대상이 바뀐다** — "어느 안이 나은가"에서 **"어떤 조건이 참이어야 하는가"**로.
   A/B/C 10축 채점 → 게이트 5 × 시나리오 3 = 15케이스 재무 판정.
4. **버리는 것을 함께 적는다.** 여섯 존 중 둘(STAY·MEMORIAL)은 1기에 짓지 않으며, 그 근거를 본문에 남긴다.
5. STEP 1~7의 슬롯·요소는 **변경 없음**. v2에서 그대로 승계한다.

### STEP 6 — 서비스 라이브러리
`S6-RAW`에 전량 나열 후 `S6-G1`~`S6-Gn`으로 그루핑.

**각 service 요소는 5축 평가를 갖는다** (v1의 `viability`를 대체·확장):
```jsonc
"eval": {
  "revenue":       "H|M|L",   // 수익성
  "brand":         "H|M|L",   // 브랜드 효과
  "difficulty":    "H|M|L",   // 운영 난이도 (H=어려움)
  "legal":         "Tier1|Tier2|Tier3",  // 법률
  "sustainability":"H|M|L"    // 지속가능성
},
"viability": { "C1":[...], "C2":[...], "C5":[...], "C6":[...] }  // 어느 선택 아래 살아남는가
```

**같은 서비스의 변주를 별개 요소로 만든다** — 대관 하나도 매스형·프리미엄형·멤버십형이 각각 다른 서비스이고 평가가 다르다.
