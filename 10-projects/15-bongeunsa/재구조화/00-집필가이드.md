# 집필 가이드 — 7단계 재구조화 리포트

> 모든 섹션 집필자가 동일하게 따른다. 이 규칙을 벗어난 조각은 조립되지 않는다.

---

## 1. 파일 구조

각 섹션은 `sections/NN-Sx.html` 조각으로 쓴다. **완전한 HTML 문서가 아니라 body 조각만** 쓴다.
`<!doctype>`, `<html>`, `<head>`, `<style>` 금지. CSS는 `build_report.py`가 붙인다.

```html
<section class="sec" id="s2" data-nav="02 재정의">
  <div class="sec-head">
    <div>
      <div class="eyebrow">Project Redefine</div>
      <h2>같은 건물을 <em>세 개의 시선</em>으로 다시 정의한다</h2>
    </div>
    <div class="no">02</div>
  </div>
  <p class="sec-desc">이 섹션이 무엇을 하는지 2~3문장.</p>
</section>

<div class="agenda">
  <div class="agenda-head">
    <div class="eyebrow">봉은사 관점 · 수익성</div>
    <div class="no">2.1</div>
  </div>
  <h3>액션 타이틀 — <em>결론을 문장으로</em> 쓴다</h3>
  <p class="lead">이 페이지의 핵심 주장 1~2문장.</p>
  ...본문...
</div>
```

- `<section class="sec">` = 단계 표지(S1~S8 각 1개). `data-nav` 속성이 좌측 네비 라벨이 된다.
- `<div class="agenda">` = **아젠다 1개 = 인쇄 시 A4 1장**. 표지 뒤에 필요한 만큼 나열한다.
- `id`는 `s1`~`s8`, 아젠다 번호는 `1.1`, `2.3` 형식.

---

## 2. 액션 타이틀 규칙 (가장 중요)

`<h3>`는 **주제어가 아니라 결론 문장**이다.

| ✗ | ✅ |
|---|---|
| 시장성 분석 | 종교의 힘은 약해졌지만 라이프스타일의 힘은 커졌다 — 그 교집합에 불교가 있다 |
| 외국인 타겟 | 외국인은 불교를 보고 갔지 경험하고 가지 못했다 |
| 법규 검토 | 세 법이 동시에 걸려 일반 상업은 전부 막혀 있다 — 합법 영역은 다섯 개뿐이다 |

핵심 단어 1~2개를 `<em>`으로 감싸면 청보라로 강조된다.

## 3. 근거 표기 — 요소 ID를 본문에 남긴다

주장·수치 뒤에 근거 요소 ID를 칩으로 단다. 이게 리포트와 `elements.json`을 잇는 유일한 끈이다.

```html
공실 3년간 누적 기회비용은 약 126억원이다<span class="ev b">E-0058</span>
```

- `class="ev a"` = confidence A (원출처 확인)
- `class="ev b"` = confidence B (2차 인용)
- `class="ev c"` = confidence C
- 브리프의 🟣A / 🔵B / ⚪C 표시를 그대로 옮긴다.
- 인쇄 시 칩은 자동으로 숨겨진다.

---

## 4. 수치 사용 정책 (엄수)

| 등급 | 규칙 |
|---|---|
| 🟣**A** | 본문에 수치 그대로 인용 가능 |
| 🔵**B** | 인용하되 **"○○ 리서치 기준"** 또는 "자체 리서치 집계" 같은 단서를 문장에 넣는다 |
| ⚪**C** | **본문 수치 인용 금지.** 정성 서술로 바꾸거나("행사 시 대규모 인파가 모인다"), 표에 넣되 `재검증 필요` 표기를 단다 |

추가 규칙:
- **연도가 다른 수치를 한 문장에 붙이지 않는다.** 붙여야 하면 각각 연도를 명시한다.
- **%와 %p를 구분한다.** 브리프에 "점 차이"라고 적힌 것은 %p가 아니다.
- 귀속을 정확히 — 브리프 `numbers`의 `context`를 확인하고, 누구의 무엇에 대한 수치인지 문장에 남긴다.
- 계산으로 유도한 값(예: 강남 방문 외국인 670만)은 "…로 추정된다"로 쓰고 유도 근거를 밝힌다.

## 5. 사용 가능한 CSS 컴포넌트

| 클래스 | 용도 |

| `.callout` / `.callout-danger` / `.callout-success` | 강조 박스 |

| `.choice-card .pro` / `.con` | 장단점 줄 (+/− 자동) |
| `.lens` + `.lt` / `h5` | **관점 블록 — S2 전용** |

| `.kpi-grid`(`-3`) + `.kpi` | 숫자 타일 |
| `.case-study` + `.case-header` / `.case-meta` / `.case-insight` | **케이스 — S5 전용** |
| `.card-grid`(`-2`/`-4`/`-5`) + `.card` | 카드 나열 |
| `.steps` + `.step` / `.step-num` | 단계 |
| `table` / `.compare-table` / `.matrix` (+ `td.hit`/`.mid`/`.out`) | 표·매트릭스 |

새 클래스를 만들지 않는다. 위 목록으로 표현되지 않으면 표나 문단으로 쓴다.

## 6. 문체

- 단정형 종결. "~로 보인다", "~일 수 있다"는 근거가 실제로 약할 때만.
- 한 문단 3~5문장. 문단 사이에 소제목(`<h4>`)을 자주 넣는다.
- 수사를 쌓지 않는다. 사실 → 해석 → 그래서 무엇 순서.
- **모르는 것은 모른다고 쓴다.** 자료 공백은 감추지 말고 `.callout-danger`로 명시한다. 이 리포트의 가치 절반은 "무엇이 비어 있는지"를 정확히 아는 데 있다.
- 없는 수치를 지어내지 않는다. 브리프에 없으면 쓰지 않는다.

## 7. 내부 전용 처리

이 리포트는 **내부 사고 문서**다. 납품물이 아니다. 다만 다음 두 곳은 특별히 표시한다.

1. **S1의 계약 방어 논리**(수정요구 방어 매트릭스, 잔존 리스크) → 제목 옆에 `<span class="internal">내부 전용</span>`
2. **S3-C3의 회색지대** → 내부본에서는 "미확정 영역(그레이존)"으로 직설하되, 반드시 다음 문장을 함께 넣는다:
   > 납품본에서는 이 항목을 "유권해석 대상 영역"으로 표기한다.

## 8. 분량

아젠다 1장 = 화면에서 스크롤 1~2회, 인쇄 A4 1장. 표 1개 + 문단 3~4개 + 강조 박스 1개 정도가 적정.
넘치면 아젠다를 쪼갠다. 모자라면 합친다.
